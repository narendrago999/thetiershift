## Website

The TierShift public website is a responsive, multi-page site published through GitHub Pages and connected to the custom domain.

The repository contains the website source, shared styling and scripts, static pages, and supporting assets and SEO files.

### Key files and resources

| Path / Resource | Purpose |
| --- | --- |
| `index.html` | Website homepage |
| `style.css` | Shared site styling |
| `script.js` | Shared client-side functionality |
| `assets/` | Images, icons, and other static assets |
| `sitemap.xml` | Sitemap for search engines |
| `robots.txt` | Search engine crawling directives |
| `ai-tools/` | AI Tools Hub pages and resources |

Individual service and information pages are maintained as part of the static website.

## Run Locally

This is a static website. You can preview it locally without installing application dependencies.

1. Clone the repository:
   ```bash
   git clone https://github.com/narendrago999/thetiershift.git
   cd thetiershift
   ```

2. Open `index.html` in your browser.

For a local HTTP server, you can use Python:
```bash
python -m http.server 8000
``

Then visit http://localhost:8000.

## Deployment

The site is published using **GitHub Pages**.

When changes are pushed to the configured publishing branch, GitHub Pages builds and serves the static site. The production website uses the custom domain:

https://thetiershift.com/

Keep internal links, canonical URLs, sitemap entries, and asset paths consistent when adding or moving pages. Verify important pages and responsive layouts after publishing.

## Contributing

This repository contains the public TierShift website. Before submitting changes:

1. Check the existing page structure, shared styles, and scripts.
2. Follow the current visual identity and responsive design patterns.
3. Preserve existing navigation, accessibility, SEO metadata, and working functionality.
4. Test changed pages and links locally.
5. Update the sitemap when adding, removing, or changing indexable public pages.

Please avoid introducing unnecessary frameworks or build tooling for simple static-site changes.
