SECURITY FIRST

Permission-aware retrieval is a design requirement

BEFORE INDEXING

Preserve source permissions

Capture document identity, ownership, classification and access-control metadata. Define how permission changes and deleted content propagate to the index.

AT QUERY TIME

Filter by the caller

Resolve the authenticated user's entitlements and enforce them in retrieval. Never rely on a prompt instruction as an access-control boundary.

AFTER GENERATION

Return evidence

Attach citations to source passages, handle insufficient evidence explicitly and log the retrieval context needed for investigation.

Important: A vector index can accidentally widen access if document permissions are not preserved and enforced. Test with users who have intentionally different access rights before launch.
AGENT CONTROL PLANE

Give agents tools with boundaries

Good candidates for automation

  • Read-only search across approved enterprise sources.
  • Drafting summaries, reports and proposed updates.
  • Retrieving operational status from approved APIs.
  • Creating tickets or workflow drafts with traceable context.

Actions that need stronger controls

  • Payments, approvals or financial transactions.
  • Changing customer, employee or production records.
  • Sending external communications or publishing content.
  • Deleting data, changing permissions or deploying code.
MEASURE WHAT MATTERS

Evaluation and operational readiness

RETRIEVAL QUALITY

Did we find the right evidence?

Measure recall and precision on representative queries, including ambiguous questions, stale content and permission-restricted documents.

ANSWER QUALITY

Is the answer grounded?

Evaluate correctness, citation support, completeness, refusal behaviour and whether the assistant admits when evidence is missing.

AGENT RELIABILITY

Did the tool do the right thing?

Test tool selection, parameter validation, retries, idempotency, approval gates and audit logging against realistic task scenarios.

COMMON QUESTIONS

Enterprise RAG and agent FAQ

Does RAG eliminate hallucinations?

No. Retrieval can improve grounding, but systems can still retrieve irrelevant evidence or generate unsupported claims. Use citations, refusal rules, evaluation and monitoring to reduce risk.

Do we always need a vector database?

No. Vector search is one retrieval method. Hybrid retrieval combining keyword and semantic search is often useful; the best design depends on content, query patterns, scale and platform constraints.

What is the difference between RAG and an AI agent?

RAG retrieves external information to ground a model response. An agent adds orchestration and may select tools or take actions. Agents need additional controls for permissions, approvals, retries and auditability.

Should every agent action require human approval?

Not necessarily. Read-only and low-risk actions may be automated within narrow permissions. High-impact or irreversible actions should use explicit approval, policy checks and traceable execution.
