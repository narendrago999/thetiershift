01 / THE REAL-WORLD SCENARIO

What is actually going wrong?

An AI assistant can unintentionally bypass the access boundaries users expect if retrieval runs with a broad service identity and does not enforce the caller's permissions on every result.

Symptoms teams commonly notice

  • A user receives content from a restricted document
  • Different users get identical answers despite different access rights
  • The retrieval service uses one broad shared credential
  • Access revocation does not take effect in the assistant
IMPORTANT DISTINCTION

Look beyond the visible symptom.

The first visible failure is not always the root cause. Trace the full workflow, preserve run-level evidence and validate the business outcome before changing production behaviour.

    04 / SOLUTION DESIGN

    How to solve it reliably

    A production solution should address the root cause, make failures observable and support safe recovery.

    1. 01
      Authenticate the user and propagate a verifiable identity context to the retrieval service.
    2. 02
      Enforce document-level ACL filters before content reaches the language model; never rely on prompt wording to hide restricted data.
    3. 03
      Use least-privilege service identities and separate administrative indexing from user-time retrieval.
    4. 04
      Define how permission changes and revocations invalidate cached results and indexed ACL metadata.
    5. 05
      Log user identity, retrieved document IDs, policy decisions and access-denial events without unnecessarily logging sensitive content.
    IMPLEMENTATION EXAMPLE
    # Illustrative retrieval guard: enforce ACL before building LLM context
principal = authenticate_request(token)
allowed_doc_ids = acl_service.allowed_documents(principal.id)

results = vector_store.search(
    query=user_question,
    filter={"document_id": {"$in": allowed_doc_ids}}
)

# Only authorised passages may be passed to the model.
context = build_context(results)

    Illustrative starting point. Validate identifiers, data types, security and platform-specific syntax in your environment before production use.

    07 / PREVENTION CHECKLIST

    Keep the problem from returning

    • Map identity and permissions: Document users, groups, source ACLs and trust boundaries.
    • Enforce before generation: Filter retrieval candidates using authoritative permissions.
    • Handle change and revocation: Synchronise ACL updates and invalidate affected caches.
    • Test adversarial access cases: Verify allowed, denied, revoked and cross-tenant scenarios.
