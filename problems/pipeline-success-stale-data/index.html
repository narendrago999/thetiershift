01 / THE REAL-WORLD SCENARIO

What is actually going wrong?

A green pipeline status is not proof that the business dataset is current. A copy can succeed with zero new rows, a watermark can skip late updates, or a downstream model can remain unrefreshed.

Symptoms teams commonly notice

  • Pipeline run is green, but dashboard figures have not moved
  • Source records are newer than the warehouse maximum timestamp
  • Only some tables or business units appear stale
  • The pipeline reports success even when the source extract is empty
IMPORTANT DISTINCTION

Look beyond the visible symptom.

The first visible failure is not always the root cause. Trace the full workflow, preserve run-level evidence and validate the business outcome before changing production behaviour.

    04 / SOLUTION DESIGN

    How to solve it reliably

    A production solution should address the root cause, make failures observable and support safe recovery.

    1. 01
      Define freshness SLAs for each critical dataset, not just a pipeline schedule.
    2. 02
      Capture a source watermark and a target watermark for every load; compare them after ingestion.
    3. 03
      Validate row counts, maximum business timestamp, expected partitions and null/duplicate thresholds before marking the dataset ready.
    4. 04
      Trigger downstream models only after validation passes; publish a freshness status that consumers can see.
    5. 05
      Use a bounded lookback window and merge by stable business key when source records can arrive late.

    07 / PREVENTION CHECKLIST

    Keep the problem from returning

    • Define freshness contract: Specify expected delay, business timestamp and acceptable late-arrival window.
    • Instrument each batch: Persist run ID, source/target counts, watermark and start/end times.
    • Add data acceptance tests: Fail the readiness gate when freshness or reconciliation checks breach the contract.
    • Orchestrate downstream work: Refresh reports only after the curated data quality gate succeeds.
